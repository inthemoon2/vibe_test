# 스펙: 발표 성장 기록 · 세특 도우미 (v2)

Status: ready-for-agent

## 배경

고1 「인공지능 기초」 사회문제 해결 기계학습 프로젝트(3차시)를 운영하는 정보 교사용 도구의 2번째 버전.
1차 발표 → 교사 피드백 → 수정 → 2차 발표 과정에서, 발표 내용·피드백·질의응답과 그 변화를 기록하고
세특(과목별 세부능력 및 특기사항)에 반영하는 일이 수작업이라 부담이 크다.

- 사용자: 교사 1명(관리자 페이지), 학생(활동지 페이지)
- 기존 버전(수업 완료)은 건드리지 않는다. 이 저장소(`inthemoon2/vibe_test`)에 복사본으로 새로 만들고,
  **구글 시트와 Apps Script도 새로 만든다.**
- 기간: 해커톤 2주, 아래 기능 전부 구현.

## 현재 구조 (기존 코드)

- `web/`: GitHub Pages 정적 사이트(바닐라 JS). `admin.html`(교사), `index.html`(학생 활동지), `report.html`.
  모든 호출은 `PJ.api(action, payload, token)` → Apps Script 웹앱 `doPost`.
- `apps-script/Code.gs`: 구글 시트 저장, HMAC 토큰, `ACTIONS` 표(pub/s/a 권한).
- 채점 기준 E1~E4(각 20) + E5 동료평가(20). 3차시 고정. 발표는 발표 자료 파일 업로드만 존재.

## 결정 사항

### 1. 로그인과 명단
- 교사는 **반별 명단(반, 학번, 이름)만** 올린다. 조·역할 포함 명단 업로드와 조 비밀번호 발급은 없앤다.
- 학생은 첫 로그인 시 학번+이름으로 들어와 **개인 비밀번호를 직접 설정**한다. 이후 학번+이름+비밀번호.
- 비밀번호 분실 시 교사가 관리자 화면에서 초기화.

### 2. 관심 분야 → 조 편성
- 학생은 로그인 후 먼저 **진로·관심 분야를 자유 서술**로 입력한다.
- 관리자 화면에 반별 명단 + 관심 분야 현황이 보인다. 교사가 반별로 **입력 마감**을 누른다.
- **AI가 6~7개 분야 묶음안**을 이름과 함께 제안한다. 반 인원에 맞춰 묶음 수를 정하고 **한 묶음 최대 5명**.
  "모르겠음" 등 불명확한 학생은 인원이 남는 묶음에 배치하고 "관심 분야 불명확"으로 표시.
- 교사는 학생을 끌어 옮기고 묶음 이름을 고친 뒤 **학생에게 공개**한다.
- **분야 묶음 1개 = 조 1개.** 묶음 이름이 조의 `분야`가 된다.

### 3. 역할 선택
- 공개 후 학생 팀홈이 묶음(조) 화면으로 바뀌고, 학생은 **자기 이름만** 역할 칸에 드래그 앤 드롭한다.
- 규칙(화면과 서버 양쪽에서 막음):
  - 데이터 엔지니어: 조당 최대 3명. 나머지 4개 역할: 조당 1명.
  - 학생 1명당 최대 2개 역할.
  - 정원이 찬 칸·이미 2개 고른 학생은 추가 불가. 동시 선택은 서버에서 먼저 저장된 쪽 인정.
- 관리자 화면에 조별 "빈 역할", "역할 없는 학생" 표시. 빈 역할이 있어도 확정 가능.
- 교사가 **조 확정** → 역할 고정, 조 ID(`C{반}-{조}`) 생성, 조별 활동지 열림. 확정 후 역할 변경은 교사만.

### 4. 학생 이동
- **교사만, 언제든지**(공개 후·확정 후 포함) 학생을 다른 조로 옮길 수 있다.
- 옮긴 학생의 역할은 비워지고 새 조에서 다시 고른다(확정 후라면 교사가 지정).
- 개인 기록(`필드@이름`, 예: 나의 기여)은 학생을 따라가고, 조 공동 기록은 원래 조에 남는다.
- 이동 기록은 로그에 남긴다.

### 5. 발표 기록 (관리자 페이지 "발표 기록" 탭)
- 발표는 차시와 별개로 **발표 회차(1차 / 2차)**로 관리. 날짜는 녹음일 자동 기록.
- **브라우저에서 실시간 녹음 + 실시간 STT.** 오디오 파일은 저장하지 않고 **텍스트만 저장**.
  - STT는 브라우저 내장 Web Speech API(크롬·엣지)로 시작. 침묵으로 끊기면 자동 재시작.
  - 나중에 클라우드 STT로 교체할 수 있게 STT 모듈을 분리한다.
- 녹음 중 버튼:
  - 구간: **발표 / 질문·답변 / 피드백**
  - 발언자: **그 조 학생 이름 버튼들 + "교사"**
  - 버튼을 누른 뒤의 글이 그 구간·발언자로 기록된다.
- 녹음 후 편집 화면에서 문단별 구간·발언자·글을 고칠 수 있다.

### 6. 발표 평가 (기존 채점 기준표와 별개)
- 항목: **설명 방법, 이론 내용, 실기 내용, 발표 자료 구성, 개선도**(1차 피드백을 2차에서 반영한 정도).
- **점수·수준 없이 서술만.** 학생별·항목별로 "1차 모습 → 피드백 → 2차 모습 → 변화".
- 기존 E1~E5 점수에는 반영하지 않는다. 목적은 세특.

### 7. AI 초안 3단계 (모두 교사가 고치고 승인)
1. **1차 피드백 정리**: 교사가 말로 한 피드백을 학생별·항목별 글로 정리.
2. **2차 변화 서술**: 학생별·항목별 "1차 → 피드백 → 2차 → 변화".
3. **세특 초안**: 승인된 변화 서술 + 기존 활동 기록(역할, 나의 기여 등)으로 학생별 세특.
- AI 초안과 교사 최종본을 **따로 저장**한다.

### 8. 1차 피드백 공개
- 교사가 승인 후 **공개 버튼**을 누르면 학생 팀홈에 표시. 조 전체 피드백은 조원 모두에게,
  개인 피드백은 본인에게만. 기존 피드백 공개·개인공개 방식을 따른다.

### 9. 세특
- **프로젝트 부분만, 기본 300자**(설정에서 조절). 나이스 과목 세특 한도 500자/1,500바이트 참고.
- 새 `세특` 시트: 반, 학번, 이름, AI 초안, 최종본, 글자수, 바이트 수, 승인 여부, 승인 일시.
- 기존 금지어 점검(대학·기업·학교명 등) 적용, 복사 버튼.
- 기존 "세특 재료" 카드는 새 세특 탭에 합친다.

### 10. AI 연결과 개인정보
- **Claude API**를 Apps Script `UrlFetchApp`으로 호출. 키는 스크립트 속성 `ANTHROPIC_API_KEY`.
  호출부는 한 곳에 모아 다른 서비스로 바꿀 수 있게 한다.
- AI에 보낼 때 **이름·학번을 가명(학생A, 학생B…)으로 치환**하고 결과를 서버에서 실명으로 복원.
  녹음 글 안의 이름도 명단과 대조해 치환.
- 관리자 화면에 "AI에 보내는 내용" 미리보기를 둔다.

### 11. 기존 기능
- 바꿈: 명단 탭 → 반별 명단 + 개인 비밀번호 초기화. 조 구성 탭 신설.
- 추가: 발표 기록 탭, 세특 탭.
- 그대로: 진행 현황, 차시별 점검, 채점(E1~E5), 채점표, 가상채점, 동료평가 가져오기,
  학생 활동지 6개 페이지, 보고서, 기존 피드백 공개.
